# Pinned OceanSim validation — 2026-11-14

The simulator uses the public fork
https://github.com/LuisCarvalho314/OceanSim at
`53c45e5c3aafa3c6ce44a344b07a082a980633ef`, recorded as a Git submodule under
`third_party/OceanSim`. Upstream is https://github.com/umfieldrobotics/OceanSim.
Both repositories retain their existing histories. The fork's upstream remote
is retained in the local submodule checkout; new clones can add it with
`git -C third_party/OceanSim remote add upstream https://github.com/umfieldrobotics/OceanSim.git`.

## Source and publication review

OceanSim commits separate existing water-grid/normal/UV and Z-up Warp projection
changes (`700afed`), Isaac Sim 6.1 extension activation/menu/API fixes (`128d1f0`),
and configurable external assets (`53c45e5`). The original BSD-3-Clause license,
copyright and attribution remain intact. The code review and credential-pattern
scan found no secrets or restricted local additions in the material selected for
publication. Both GitHub repositories were confirmed public before publication.
Downloaded assets and NVIDIA libraries remain external and retain their own terms.
No new binary assets are published. Large demo/media files already in upstream
history are inherited; history is not rewritten to remove them.

`WaterSurface.py.bak` has no unique substantive implementation; its indentation
predates the selected source. It remains in the original installation alongside
all diagnostics, captures, logs, caches and the original machine-specific
`asset_path.json`. None of those local additions is included in the fork.
The fork removes the upstream example asset registration from the current tree
and ignores local registrations. `OCEANSIM_ASSET_PATH` or the existing registration
script selects an external asset directory.

In `rov-sim`, outputs, datasets, profiling captures, caches, local environment files
and generated tank snapshots are excluded. The three previously tracked
`generated_tank/` files are removed only from the index; their working files are
preserved and can be regenerated by the simulator. The existing small `Poolv1.usd`
and historical tank builder remain unchanged. Historical reports retain local
paths as provenance; launch and reproduction settings use configurable paths.

Jazzy workspace, installed outside the repository and outside Isaac Sim:

```powershell
winget install prefix-dev.pixi
# A short root avoids the 260-character MAX_PATH limit inside .pixi\envs.

$env:ROV_SIM_PIXI_ENV = 'C:\IsaacSim-ros_workspaces\jazzy_ws\.pixi\envs\default'
```

## Reproduce

Follow the [README](../README.md) for fresh clone, submodule initialization,
external assets, runtime selection, CameraSensor launch, validation and benchmarks.
For a short check, use its geometric command and set `--frames 12` on the selected
photometric change-detection command. For the full matched comparison use
`rov_sim/tools/benchmarking/camera_backend_suite.py`, followed by `rov_sim/tools/benchmarking/compare_camera_backends.py` and
`rov_sim/tools/validation/verify_camera_scene.py`. Those tools include frame freshness, stale-pose rejection,
saved-buffer equations, scene preservation and the fork source-hash audit.

For MCAP recording, set `ROV_SIM_PIXI_ENV` and run `./scripts/validate_mcap.ps1
-EvidenceRoot <new dir>`, then the WSL first-bag steps in [VALIDATION.md](VALIDATION.md).

Use fresh evidence roots after the repository cleanup; historical suite provenance
intentionally cannot resume with the moved sources. The unchanged Script Editor
reference is now `legacy/rov_tank_builder.py`, and the earlier runtime report is
[archived](archive/RUNTIME_VALIDATION_2026-11-04.md). Recorded findings and source
identities above remain historical evidence.
