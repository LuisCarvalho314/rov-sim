# Isaac Sim stereo ground truth to MCAP: review decisions and validation plan

This plan records the pre-implementation review. Route C passed the [spike](#spike-result).
The 2026-11-17 route change below informed the [implemented design](docs/designs/isaac-stereo-mcap.md),
including items 1, 3, 4 and 6 and the launcher decision.

This plan amends [concepts_brief.md](concepts_brief.md), which remains the governing feature spec: problem and overview, [goals and non-goals](concepts_brief.md#goals-vs-non-goals), [alternatives](concepts_brief.md#alternatives-weighed) and [risks](concepts_brief.md#remaining-risks-for-option-c). It records the decisions taken after the brief's [zoom-out review](zoom_out_report.md) and the interactive review that followed. The brief's [carried-forward decisions 1-7](concepts_brief.md#key-decisions--staging-for-next-steps) still stand unless amended below.

## Review decisions

- **Route change (2026-11-17; amends "Pinning", "Launcher", "Route C" and work items 1, 3, 4 and 6):** the writer is ROS 2's own `rosbag2_py.SequentialWriter` (MCAP storage) running in Kit's process, loaded from NVIDIA's Pixi workspace `IsaacSim-ros_workspaces` at tag `IsaacSim-6.1.0` through a minimal in-process overlay (`rov_sim/rosbag/deps.py`); `launch.ps1` is unchanged. rosbag2 writes `metadata.yaml` and QoS, so no WSL `ros2 bag reindex` is needed, and each pass is checked in-process before it is renamed out of `mcap/.staging/`. Route C becomes the fallback, rebuilt from commit `c279b8f` (reverted) if the overlay stops working. Evidence: [native ROS 2 recording research](native_ros2_recording_research.md) and the design's overlay spike. Work item 5 keeps its benchmark, with storage `none` and `zstd` (rosbag2 `zstd_fast`) instead of lz4/zstd chunks. The first-bag reprojection of the diagnostic target (item 4) is not part of this change; geometry is covered by the bag check and the contract tests.

- **MCAP container library: the `mcap` Python package** (resolves brief open question 1). It writes only the container; serialization stays with the bundled `rclpy.serialization`. Alternatives rejected:
  - A hand-written writer (brief option 2): about 200 lines of CRC, chunk and summary-index code to write, test and maintain, which is the part most likely to have subtle format bugs.
  - Uncompressed, unchunked MCAP (option 3): larger files (about 2.2 GB per 1,000 frames), no summary index, and no chunk-level recovery after a crash.

  The cost of this choice is a dependency outside git. `mcap` 1.6.0 (checked 2026-11-16) is a pure-Python wheel but requires the native `lz4` and `zstandard` packages, so wheels for Kit's bundled Python on Windows must be available. The spike also checks whether uncompressed writing works without them.
- **Pinning (superseded by the route change):** Kit's bundled Python stays unmodified (README rule). `mcap`, `lz4` and `zstandard` are installed with uv into a gitignored `.kit-venv/` created from Kit's interpreter with `--system-site-packages`, from the hash-locked `requirements-kit.txt` (see work item 1). Check the versions at startup when the MCAP flag is on, update the README statements that no packages are installed, and add the install step to `docs/REPRODUCIBILITY.md`.
- **Launcher (decided 2026-11-16 after the spike; amends "Pinning" and items 1 and 6; superseded by the route change, no `.kit-venv`):** Isaac Sim's own `python.bat` stays the launcher, with a process-local `PYTHONPATH` entry for `.kit-venv\Lib\site-packages`. `.kit-venv` is a hash-locked install target managed by uv, **not** the runtime interpreter. The `PYTHONEXE` venv launcher is not used: the venv's redirector runs the interpreter as a `python.exe` child instead of `kit.exe`, so the NVIDIA driver profile is lost (see [Spike result](#spike-result), item 1). Kit's Python and NVIDIA's `python.bat` are not modified. Requirements:
  - keep the existing Kit executable (`kit.exe`) and driver profile;
  - keep argument handling, `python.bat`'s environment setup, subprocess return codes and benchmark compatibility;
  - verify that the MCAP packages resolve from `.kit-venv` and that NumPy stays Kit's 2.3.1;
  - append the bundled ROS 2 Python path (`exts/isaacsim.ros2.core/jazzy/rclpy`) so that its NumPy 2.5.1 never takes precedence;
  - keep the dependency bootstrap separate from the MCAP-writing logic;
  - add a targeted rendering and shutdown regression test;
  - document the observed rosbag2 QoS limitation (no `offered_qos_profiles`; `/tf_static` replays as volatile).

  No additional ROS 2 environment, Pixi installation or `rosbag2_py` dependency is authorised. The `rosbag2_py.SequentialWriter` side check in item 2 is closed.
- **Route C stays conditional on the spike (work item 2).** The spike passes when WSL `ros2 bag reindex <dir> -s mcap` succeeds; `rosbag2_py` reads every topic; the MCAP header profile is `ros2`; message and schema encodings are `cdr` and `ros2msg`; every schema includes the definitions of all its nested types; and every message deserializes in WSL with `rclpy.serialization.deserialize_message` to the values written (stamps, frame ids, CameraInfo, image size and encoding). The spike records the QoS metadata reindex produces, without a pass criterion, because `/tf_static` is repeated in every bundle. Consumer acceptance (`bag_to_capture` and `rov_slam` evaluation reading the bag unchanged) stays a first-bag criterion (brief staging step 3). If a check fails:
  - `mcap` with compression cannot be installed in Kit's bundled Python: try `mcap` with uncompressed chunks; if that also fails, block and choose between the hand-written writer and unchunked MCAP, accepting the costs recorded above.
  - The `.msg` files are missing from Jazzy `share/`: embed the schema text (brief risks).
  - `serialize_message` fails in Kit: route C fails (brief decision 1); block and return to design. Candidates are a hand-written CDR encoder or an out-of-process writer.
  - `reindex` rejects the file: fix and retry; block if the cause is in the route rather than in the file.

  Work items 3-5 start only after item 2 passes; item 6 can start with identifying the affected docs.
- **`metadata.yaml`: produced by WSL `ros2 bag reindex`** for the first bag (resolves brief open question 2). Revisit writing it from the simulator if the extra WSL step blocks a consumer workflow.
- **Frame manifest: removed** (amends brief decision 7 and goal "a frame manifest and a completeness check"). Missing frames and incomplete bundles are detected from `status.json` `completed_frames`, the stamp formula and the bag itself (work item 4). The completeness check stays.
- **Documentation** (resolves brief open question 3): rov-sim docs, plus a docs-only `rov_ws` branch for its MCAP contract README and any docs that describe HoloOcean-only requirements. Docs-only changes do not count against the non-goal "changes to `rov_ws` code". Update docs in the same branch as the implementation; see work item 6.

## Remaining work before implementation planning

These items settle what the spike and measurements must decide. They are not the implementation plan. That plan, with build items, exact file paths and a test plan, is written after item 2 passes, because several of its answers depend on the spike (see the gate above). It must cover brief decisions 1-7 and the first-bag criteria (brief staging step 3), and decide: the flag name and its interaction with `--record`, `--benchmark` and `--preview-mp4`; where non-`camera-sensor` backends are rejected; the per-pass directory layout inside the run directory; the stamp epoch; `/tf` content; chunk compression and size; and the tests, including the brief's known-colour pixel check, the flag-off regression checks in item 0, and edge cases (empty pass, disk full, crash before rename, missing `.msg`, version mismatch).

0. **Baseline.** Commit the pending `rov_sim/` restructure alone on `main`, excluding the report `.md` files and `.idea/`, and tag it. Create `feature/isaac-mcap` in rov-sim and `docs/isaac-mcap` in `rov_ws` (brief staging step 1). Git reversibility and flag-off behaviour are measured against this tag. With the flag off, deterministic outputs (CLI and config validation results, recorded poses, output file layout, `status.json` apart from times and durations) must be byte-identical; the MCAP module must not be imported; the existing tests and validation checks must pass. Rendered images are not byte-compared, because RTX output is not bitwise repeatable (`README.md`, `docs/VALIDATION.md`). `requirements-kit.txt` and the `.kit-venv/` entry in `.gitignore` go on the feature branch.
1. **Install** (amended by the route change: Pixi workspace, not `.kit-venv`). Run from native Windows, as Isaac Sim documents for its bundled Python (`python.bat -m pip install`); an earlier install attempted from WSL failed with an untrusted mount-point error. Kit's bundled Python stays unmodified. Create `.kit-venv/` (gitignored) with `uv venv --python <Kit's python.exe> --system-site-packages`, lock `mcap`, `lz4` and `zstandard` with hashes into `requirements-kit.txt`, and install them with `uv pip install --python .kit-venv -r requirements-kit.txt`. The spike records, under the venv launcher and under plain `python.bat`: `sys.executable` and `sys.prefix`; the resolved file path and version of `mcap`, `lz4`, `zstandard` and `numpy`. The pinned packages must resolve into `.kit-venv` and `numpy` must resolve to the same Kit path under both launchers. The spike confirms that Isaac Sim starts from the venv interpreter with `python.bat`'s environment setup applied (`scripts/runtime.ps1` then launches through it), that `lz4` and `zstandard` load, and whether uncompressed writing works without them. The startup check aborts with a message naming the expected and found versions.
2. **Spike.** In a scratch script run from `.kit-venv` with `python.bat`'s environment setup (not committed): check `rclpy.serialization.serialize_message`, check whether Jazzy `share/` contains the `.msg` files, and write a sample containing at least one message on each of the seven contract topics at full image size. Apply the pass criteria and failure branches in the route decision above. Separately, and limited to one working day without blocking route C: check whether `rosbag2_py.SequentialWriter` with `mcap` storage from Isaac Sim 6.1's Pixi/RoboStack ROS 2 Jazzy environment can write a bag from inside Isaac Sim's process, with no middleware transport. A separate writer process is out of scope, because it would need an inter-process channel. If the check passes, return the writer and reindex route to design before implementation planning; if it fails or runs over its time limit, record why and continue with route C. Record the outcome, the branch taken and the resolved versions in a "Spike result" section of this document.
3. **Output finalization** (amended by the route change: no reindex; states `writing`/`failed`/`check_failed`/`complete`). Extend the existing run status in `rov_sim/application.py` (`status.json`: `running_<pass>`, `complete`, `failed`, `interrupted`) rather than adding a second mechanism. A pass is **written** when `status.json` marks it complete and the MCAP file has a valid summary and footer, and **complete** only when reindexing has also succeeded and the completeness check in item 4 passes. Consumers read only complete passes. A written pass whose reindex failed needs only a repeated reindex; a pass that was not written is never presented as complete. The implementation plan decides the staging directory name, whether `reindex` runs before or after the rename, and the recovery steps for a failed pass.
4. **Completeness and consumers** (amended by the route change: target reprojection deferred). A frame bundle is the seven contract topics sharing one stamp (brief decision 6). The loop never skips a frame (an unready pair fails the run), so completeness is checked without a manifest: the bag's stamps for a pass equal `{epoch + i·10⁹ // fps : i < completed_frames}` from `status.json`, and every stamp has all seven topics. The first bag also runs with the existing stereo diagnostics enabled and checks that the decoded bag reproduces their validated geometry: the diagnostic target reprojected with the bag's pose and CameraInfo K lands on the pixel the diagnostics measured; `/tf_static` equals the left-to-right transform the simulator validates (+0.38 m along left optical x, no rotation); and the sign of the right P[0,3] gives the measured disparity. The known-colour pixel check (brief decision 5) stays. Depth conventions belong to the depth milestone. `bag_to_capture` and `rov_slam` evaluation acceptance are first-bag criteria. Also test `rov_mapping` replay, or record in the brief that the compatibility claim for it is deferred.
5. **Throughput and disk.** Run `--benchmark` with the MCAP flag on over 40 CameraSensor pairs and compare with the matching 40-pair baseline in `docs/REPRODUCIBILITY.md` (12.8005 pairs/s; the brief's 12.6 is the separate full-output figure in `docs/RTX_CAMERA_6_1.md`). The benchmark already reports per-frame `recording_ms` and `iteration_total_ms`. Repeat with uncompressed, lz4 and zstd chunks at the writer's default chunk size, recording bytes per frame and `recording_ms` for each; if compression saves little, the implementation plan uses uncompressed chunks and drops `lz4` and `zstandard` where `mcap` allows. A configured run (two 60-frame passes, `configs/tank.yaml`) is close in length to the benchmark, so no separate sustained test is needed unless runs much longer than that are planned. The implementation plan decides disk-full behaviour.
6. **Documentation** (scope as decided above; amended by the route change: Pixi install instead of uv/`.kit-venv`). In rov-sim: `README.md` (recording command, output layout, module table, benchmark-recording note, and the three statements that no packages are installed into Isaac Sim), `docs/REPRODUCIBILITY.md` (uv, `requirements-kit.txt` and `.kit-venv` install step, and the venv launcher in `scripts/runtime.ps1`) and `docs/VALIDATION.md`. In the `rov_ws` docs branch: `src/rov_dataset_player/README.md`, limited to statements Isaac bags break (map rebasing, `initial_left_camera_optical_frame`, the nominal calibration file, HoloOcean metadata keys). Identifying the sections can start now; the updates land with the implementation, and documented commands are checked against the implemented behaviour.

## Spike result

Run 2026-11-16 on Isaac Sim `6.1.0-rc.26` (source build, `C:\isaacsim\_build\windows-x86_64\release`, Kit kernel 110.3.0, CPython 3.12.13) and WSL Ubuntu ROS 2 Jazzy (`ros-jazzy-rosbag2-storage-mcap` 0.26.11). Scratch scripts and sample bags were kept outside the repository and not committed.

**Outcome: route C passes. Branch taken: none of the failure branches.** Work items 3-5 may start once the implementation plan is reviewed.

### Item 0: baseline

- `main` commit `529b8de` holds only the `rov_sim/` restructure (report `.md` files, `.idea/`, `egm_review_rov_sim_review_plan/` and `docs/designs/` left untracked). Before committing, `python -m unittest discover -s tests -q` passed: 51 tests.
- Annotated tag `baseline/isaac-mcap` on `529b8de`. Branch `feature/isaac-mcap` created from the tag; commit `c279b8f` adds `requirements-kit.txt` and the `.kit-venv/` ignore entry. Nothing is pushed.
- `rov_ws`: branch `docs/isaac-mcap` created from `main` without checkout (the working copy stays on `feat/oscd-playback-controls` with its untracked files).

### Item 1: install

- `requirements-kit.txt` (hash-locked, binary wheels only, `--python-platform x86_64-pc-windows-msvc --python-version 3.12`): `mcap==1.6.0`, `lz4==4.4.5`, `zstandard==0.25.0`, all cp312 win_amd64 wheels. Installed with `uv pip install --python .kit-venv --require-hashes -r requirements-kit.txt`.
- Resolution under the `PYTHONEXE=.kit-venv\Scripts\python.exe` launcher: `sys.executable` = `.kit-venv\Scripts\python.exe`, `sys.prefix` = `.kit-venv`, `sys.base_prefix` = Kit's `kit\python`; the three packages resolve into `.kit-venv\Lib\site-packages`.
- Resolution under plain `python.bat` with `PYTHONPATH=<repo>\.kit-venv\Lib\site-packages` (the chosen launcher): `sys.executable` = `kit\python\kit.exe`, and the interpreter process image is `kit.exe` with `cmd.exe` as its parent. The three packages resolve into `.kit-venv\Lib\site-packages`.
- Plain `python.bat` without the `PYTHONPATH` entry: the three packages are absent, so Kit's Python is unmodified. `numpy` 2.3.1 resolves to the same Kit path in every case: `extscache/omni.kit.pip_archive-0.0.0+00c488ae.wx64.cp312/pip_prebundle/numpy`.
- Startup: `python -m rov_sim --config configs/tank.yaml --headless --startup-only` prints "SimulationApp and OceanSim startup succeeded", exits 0 and logs no `[Error]` lines under plain `python.bat` and under the `PYTHONEXE` venv launcher (with `OCEANSIM_ASSET_PATH` set; without it OceanSim's sample module fails to import under either). Startup under the chosen launcher, `python.bat` with the `PYTHONPATH` entry, has not been run separately. The implementation's runtime checks cover it.
- `lz4` and `zstandard` load. Uncompressed writing works with both blocked from import, so `mcap` itself does not need them.
- Finding behind the launcher decision: `python.bat` copies `python.exe` to `kit.exe` and runs that, because the DirectX driver matches its Omniverse profile by process name. The uv venv `python.exe` is a redirector that starts Kit's base `python.exe` as a child process, so under the venv launcher the interpreter runs as `python.exe` behind an extra parent process. Copying the redirector to `kit.exe` does not help; it still starts `python.exe`.

### Item 2: spike

- **Serialization:** `rclpy.serialization.serialize_message` works in Kit's Python both standalone and inside a live headless `SimulationApp`, with `isaacsim.ros2.core` **not** enabled. The bundled rclpy is at `exts/isaacsim.ros2.core/jazzy/rclpy`. That directory also ships `numpy` 2.5.1, so it must be **appended** to `sys.path`, as `isaacsim.ros2.core` itself does; inserting it first shadows Kit's numpy and fails with `DLL load failed while importing _multiarray_umath`.
- **Schemas:** the `.msg` files are present in `exts/isaacsim.ros2.core/jazzy/share/<pkg>/msg/` (`sensor_msgs`, `std_msgs`, `builtin_interfaces`, `geometry_msgs`, `tf2_msgs`). Schema text was built from them, with nested types appended in `ros2msg` form (a line of 80 `=` characters, then `MSG: pkg/Type`). No embedded schema text is needed.
- **Sample:** 3 frames at 752×480 on all seven contract topics (`/stereo/{left,right}/image_raw` `bgr8`, `/stereo/{left,right}/camera_info`, `/ground_truth/pose`, `/tf_static`, `/tf` with `map → left_camera_optical_frame`), stamps `epoch + i·10⁹ // 30` (spike-only epoch 1.7·10¹⁸ ns), each stamp used as header stamp, log time and publish time. Variants: zstd, lz4, uncompressed, uncompressed with `lz4`/`zstandard` blocked, and zstd written inside `SimulationApp`. All were written under the `PYTHONEXE` launcher; the chosen launcher resolves the same package files.
- **Pass criteria, all five variants pass:**
  - WSL `ros2 bag reindex <dir> -s mcap` completes.
  - `rosbag2_py.SequentialReader` reads all seven topics, 3 messages each, with `serialization_format` `cdr` and the expected types.
  - The MCAP header profile is `ros2`, every schema encoding is `ros2msg`, and every channel message encoding is `cdr`.
  - Schema completeness: all 21 messages decode with `mcap-ros2-support`, which uses only the embedded schema text.
  - In WSL, `deserialize_message` reproduces the values written: header stamp equals log time; frame ids; image size, `bgr8` and step; the known-colour pixel and the background colour (so the RGB to BGR swap is correct); CameraInfo K, D = 0, R = I and right P[0,3] = −fx·0.38; the pose `frame_id` `map` and position; `/tf_static` with exactly one `left → right` transform of +0.38 m and no rotation; `/tf`. Every stamp has all seven topics.
- **QoS recorded (no criterion):** reindex wrote `offered_qos_profiles: []` for every topic, because the writer stores no QoS channel metadata. For `ros2 bag play`, `/tf_static` therefore falls back to the default volatile QoS rather than transient-local. `bag_to_capture` reads `/tf_static` from every bundle and is unaffected. This limitation is documented (launcher decision).
- **Chunking:** at the default 1 MiB chunk size, each 1.08 MB image lands in its own chunk (7 chunks for 3 frames). The spike's file sizes say nothing about compression, because the synthetic images are uniform colour; item 5 measures real frames.
- **`rosbag2_py.SequentialWriter` side check: not run, and now closed.** This source build's bundled Jazzy has no `rosbag2_py` or MCAP storage plugin, and its `pixi.toml` defines no RoboStack/ROS 2 environment. The launcher decision authorises no such environment.
